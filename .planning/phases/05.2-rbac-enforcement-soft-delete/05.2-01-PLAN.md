Create a new file `lib/rbac-guards.ts` with the following exports:

1. **PermissionError class**: Extends Error, has name='PermissionError', accepts custom message defaulting to "Insufficient permissions"

2. **requireTeamRole(teamId: string, userId: string, requiredRole: TeamRole): Promise<TeamRole>**
   - Fetches TeamMember record for (teamId, userId)
   - Throws PermissionError("Not a team member") if not found
   - Implements role hierarchy: OWNER(5) > ADMIN(4) > EDITOR(3) > COMMENTER(2) > VIEWER(1)
   - Throws PermissionError(`Requires {requiredRole} role`) if actual role rank < required role rank
   - Returns the resolved actual role on success
   - Import: TeamRole type from @/prisma/generated-client, prisma from @/lib/prisma

3. **requireProjectRole(projectId: string, userId: string, requiredRole: ProjectRole): Promise<ProjectRole>**
   - Fetches Project with nested ProjectMember for (projectId, userId)
   - Throws PermissionError("Project not found") if project doesn't exist
   - Throws PermissionError("Not a project member") if user is not in project.members
   - Implements role hierarchy: OWNER(4) > EDITOR(3) > COMMENTER(2) > VIEWER(1)
   - Throws PermissionError(`Requires {requiredRole} role`) if actual role rank < required role rank
   - Returns the resolved actual role on success
   - Import: ProjectRole type from @/prisma/generated-client

4. **assertTeamMember(teamId: string, userId: string): Promise<void>**
   - Simple check: does a TeamMember record exist for (teamId, userId)?
   - Throws PermissionError("Not a team member") if not found
   - Returns void on success (fire-and-forget validation)
   - Used by createProject to ensure caller is on the team before creating a project in it

All role hierarchy constants should be defined as const objects with string keys mapping to numeric ranks, making it easy to inspect and extend. Include JSDoc comments explaining the hierarchy and when each validator should be used.
