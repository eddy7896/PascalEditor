  <action>
    1. Install use-debounce in apps/editor: from repo root run `cd apps/editor && bun add use-debounce@^10` (use bun — repo uses bun.lock).
    2. In apps/editor/app/dashboard/actions.ts, add a new exported async server action `searchProjects` with signature:

       ```ts
       export async function searchProjects(input: {
         query?: string;
         sort?: 'name' | 'modified' | 'opened';
         filter?: 'all' | 'recent' | 'starred' | 'archived';
         teamId?: string | null;
       }) { ... }
       ```

       Implementation rules (follow research file lines 152-213 and 648-705):
       - Get session via `getServerSession(authOptions)`; pull userId from `(session?.user as { id?: string })?.id`. Throw "Unauthorized" if missing.
       - Build `where` filter restricting to projects whose `team.members.some.userId === userId`.
       - If `teamId` provided, add `where.teamId = teamId`.
       - If `filter === 'archived'` set `where.deletedAt = { not: null }`; else `where.deletedAt = null`. (Honors Phase 5.2 soft-delete.)
       - If `query?.trim()` is non-empty, set `where.name = { contains: query.trim(), mode: 'insensitive' }`.
       - For now sort param is accepted but only `name` (asc), `modified` (updatedAt desc), and `opened` (lastOpenedAt desc, nulls last) implemented; default to name asc.
       - `select` minimal fields: id, name, teamId, team { select: { id, name } }, thumbnailUrl (if exists in schema; otherwise omit), updatedAt, lastOpenedAt, deletedAt, createdAt.
       - Return the array directly (no wrapper).

    3. Do NOT remove or alter existing `getDashboardData` or other actions. Only ADD `searchProjects`.
    4. Verify `lastOpenedAt` and `deletedAt` exist on Project model in prisma/schema.prisma before referencing; if `lastOpenedAt` does not exist, fall back to `updatedAt` for the `opened` sort and document in inline comment.
    5. Avoid using `mode: 'insensitive'` if the database is SQLite (research uses Postgres). Check schema.prisma datasource — if provider is `postgresql`, use it; otherwise omit `mode` and use `contains` only with a comment noting the limitation.
  </action>

  </verify>
