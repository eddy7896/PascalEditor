**URL-driven project search via Prisma case-insensitive contains + useDebouncedCallback(300ms) updating ?q= searchParam**

## Accomplishments
- `searchProjects` server action: scoped to user's team memberships, honors soft-delete, case-insensitive name filter, sort by name/modified/opened, optional teamId narrowing
- `SearchInput` client component: 300ms debounce via `useDebouncedCallback`, updates `?q=` URL param without full navigation, clears param when input emptied
- `/dashboard/projects` page refactored to async searchParams (Next.js 16), delegates project fetching entirely to `searchProjects`

## Decisions Made
- URL searchParams as source of truth (not React state) — results are bookmarkable and work with server rendering
- PostgreSQL `mode: 'insensitive'` used (schema.prisma datasource confirmed as postgresql)
- `description` field not fetched in `searchProjects` (not displayed in ProjectsGrid card); mapped to `null` in page
- `getDashboardData` retained for teams list (CreateProjectModal) and starredProjectIds; only project list replaced

## Deviations from Plan

None — plan executed exactly as written. Type inference for Prisma `where`/`orderBy` required using `Prisma.ProjectWhereInput` and `Prisma.ProjectOrderByWithRelationInput` directly instead of `Parameters<typeof prisma.project.findMany>[0]` (which resolved to `undefined`-unioned type). Resolved inline without plan change.

## Issues Encountered
- `Parameters<typeof prisma.project.findMany>[0]["where"]` resolved to a type that included `undefined`, preventing property assignment. Fixed by importing `Prisma` namespace and using `Prisma.ProjectWhereInput` directly.

None — no external service configuration required.
