## Summary

Phase 5.3 adds three critical UX features to the dashboard: **server-side project search** via URL parameters and Prisma queries, **breadcrumb navigation** showing the current location hierarchy, **sort/filter controls** on the project grid, and a **settings page** for profile and password management.

The phase builds on the soft-delete and RBAC enforcement from Phase 5.2 and applies the same patterns: server-side data fetching, permission guards, and database-driven state. All features integrate into the existing dashboard layout without requiring new frameworks or architectural changes.

**Primary recommendation:** Implement search via URL parameters (searchParams) + debounced client input → Prisma `contains` filtering + case-insensitive mode for case-agnostic search on project name.

### Pattern 1: Server-Side Search via URL Parameters + Debounce

**What:** Client captures search input with debounce delay (300ms), updates URL searchParams → server-side page re-renders with Prisma query filtered by project name (case-insensitive).

**When to use:** Any searchable list where bookmarkable URLs and SSR are beneficial; reduces client-state complexity.

**Example:**

Client component:
```typescript
'use client';
import { useDebouncedCallback } from 'use-debounce';
import { useRouter, useSearchParams, usePathname } from 'next/navigation';

export function SearchInput({ placeholder }: { placeholder: string }) {
  const searchParams = useSearchParams();
  const pathname = usePathname();
  const router = useRouter();

  const handleSearch = useDebouncedCallback((term: string) => {
    const params = new URLSearchParams(searchParams);
    if (term.trim()) {
      params.set('q', term.trim());
    } else {
      params.delete('q');
    }
    router.replace(`${pathname}?${params.toString()}`);
  }, 300);

  return (
    <input
      type="text"
      placeholder={placeholder}
      defaultValue={searchParams.get('q') ?? ''}
      onChange={(e) => handleSearch(e.target.value)}
      className="w-full bg-zinc-800/60 border border-zinc-700 rounded-lg px-4 py-2 text-white placeholder-zinc-500 focus:outline-none focus:border-indigo-500"
    />
  );
}
```

Server action:
```typescript
export async function searchProjects({
  query,
  sort = 'name',
  filter = 'all',
  teamId = null,
}: {
  query: string;
  sort?: 'name' | 'modified' | 'opened';
  filter?: 'all' | 'recent' | 'starred' | 'archived';
  teamId?: string | null;
}) {
  const session = await getServerSession(authOptions);
  const userId = (session?.user as { id?: string })?.id;
  if (!userId) throw new Error('Unauthorized');

  let where: any = {
    team: {
      members: {
        some: { userId },
      },
    },
  };

  // Filter by team if specified
  if (teamId) {
    where.teamId = teamId;
  }

  // Search: case-insensitive contains on project name
  if (query.trim()) {
    where.name = {
      contains: query.trim(),
      mode: 'insensitive',
    };
  }

  // Apply filter
  if (filter === 'archived') {
    where.deletedAt = { not: null }; // Soft-deleted projects
  } else {
    where.deletedAt = null; // Active projects only
  }

  // Sorting
  let orderBy: any = { createdAt: 'desc' };
  if (sort === 'name') {
    orderBy = { name: 'asc' };
  } else if (sort === 'modified') {
    orderBy = { updatedAt: 'desc' };
  } else if (sort === 'opened') {
    orderBy = { lastOpenedAt: { sort: 'desc', nulls: 'last' } };
  }

  return prisma.project.findMany({
    where,
    orderBy,
    include: {
      team: { select: { id: true, name: true } },
    },
  });
}
```

### Pattern 2: Breadcrumb Navigation with Context + DB Lookups

**What:** Breadcrumb component derives segment labels from URL pathname AND database lookups (team name, project name). Uses React Context to allow child pages to override breadcrumb labels dynamically.

**When to use:** When breadcrumb labels depend on entity names from the database (e.g., showing team name instead of teamId).

**Example:**

Context provider in layout:
```typescript
'use client';
import { createContext, useState, ReactNode } from 'react';

export const BreadcrumbContext = createContext<{
  labels: Record<string, string>;
  setLabel: (key: string, label: string) => void;
} | null>(null);

export function BreadcrumbProvider({ children }: { children: ReactNode }) {
  const [labels, setLabels] = useState<Record<string, string>>({});

  return (
    <BreadcrumbContext.Provider
      value={{
        labels,
        setLabel: (key, label) => setLabels((prev) => ({ ...prev, [key]: label })),
      }}
    >
      {children}
    </BreadcrumbContext.Provider>
  );
}
```

Breadcrumb component:
```typescript
'use client';
import Link from 'next/link';

export function BreadcrumbNav() {

        const label = breadcrumbContext?.labels[segment] || segment;
        return (
          <div key={segment}>
            <ChevronRight className="w-4 h-4 mx-1 inline" />
            <Link href={href} className="hover:text-zinc-300">
              {label}
            </Link>
          </div>
        );
      })}
    </div>
  );
}
```

```typescript
  const breadcrumbContext = useContext(BreadcrumbContext);
  useEffect(() => {
    if (breadcrumbContext && teamName) {
```

### Pattern 3: Sort and Filter Controls with URL State

**What:** Dropdown UI components for sort order (name, last modified, last opened) and filter type (all, recent, starred, archived). Each selection updates URL params without full navigation.

**When to use:** Multi-faceted data listing where users need quick filtering and sorting.

**Example:**

```typescript
'use client';
import { useRouter, useSearchParams, usePathname } from 'next/navigation';
import { ChevronDown } from 'lucide-react';
import { useState } from 'react';

export function SortFilterControls({ currentSort, currentFilter }: any) {
  const router = useRouter();
  const searchParams = useSearchParams();
  const pathname = usePathname();
  const [sortOpen, setSortOpen] = useState(false);
  const [filterOpen, setFilterOpen] = useState(false);

  const updateParam = (key: string, value: string) => {
    const params = new URLSearchParams(searchParams);
    params.set(key, value);
    router.replace(`${pathname}?${params.toString()}`);
  };

  return (
    <div className="flex gap-3 mb-6">
      {/* Sort dropdown */}
      <div className="relative">
        <button
          onClick={() => setSortOpen(!sortOpen)}
          className="flex items-center gap-2 px-4 py-2 bg-zinc-800/60 border border-zinc-700 rounded-lg text-zinc-400 hover:text-white transition-colors"
        >
          Sort: {currentSort}
          <ChevronDown className="w-4 h-4" />
        </button>
        {sortOpen && (
          <div className="absolute top-full mt-1 bg-zinc-800 border border-zinc-700 rounded-lg shadow-lg z-10">
            {['name', 'modified', 'opened'].map((opt) => (
              <button
                key={opt}
                onClick={() => {
                  updateParam('sort', opt);
                  setSortOpen(false);
                }}
                className="block w-full text-left px-4 py-2 hover:bg-zinc-700 text-zinc-300"
              >
                {opt === 'modified' ? 'Last Modified' : opt === 'opened' ? 'Last Opened' : 'Name'}
              </button>
            ))}
          </div>
        )}
      </div>

      {/* Filter dropdown */}
      <div className="relative">
        <button
          onClick={() => setFilterOpen(!filterOpen)}
          className="flex items-center gap-2 px-4 py-2 bg-zinc-800/60 border border-zinc-700 rounded-lg text-zinc-400 hover:text-white transition-colors"
        >
          Filter: {currentFilter}
          <ChevronDown className="w-4 h-4" />
        </button>
        {filterOpen && (
          <div className="absolute top-full mt-1 bg-zinc-800 border border-zinc-700 rounded-lg shadow-lg z-10">
            {['all', 'recent', 'starred', 'archived'].map((opt) => (
              <button
                key={opt}
                onClick={() => {
                  updateParam('filter', opt);
                  setFilterOpen(false);
                }}
                className="block w-full text-left px-4 py-2 hover:bg-zinc-700 text-zinc-300"
              >
                {opt.charAt(0).toUpperCase() + opt.slice(1)}
              </button>
            ))}
          </div>
        )}
      </div>
    </div>
  );
}
```

Server actions:
```typescript
'use server';
import { prisma } from '@/lib/prisma';
import { getServerSession } from 'next-auth/next';
import { authOptions } from '@/lib/auth';
import bcrypt from 'bcryptjs';

export async function updateUserProfile(input: { name?: string; image?: string }) {
  const session = await getServerSession(authOptions);
  const userId = (session?.user as { id?: string })?.id;
  if (!userId) throw new Error('Unauthorized');

  const updatedUser = await prisma.user.update({
    where: { id: userId },
    data: {
      name: input.name?.trim(),
      image: input.image?.trim(),
    },
  });

  return { success: true, user: updatedUser };
}

export async function changePassword(input: { currentPassword: string; newPassword: string }) {
  const session = await getServerSession(authOptions);
  const userId = (session?.user as { id?: string })?.id;
  if (!userId) throw new Error('Unauthorized');

  const user = await prisma.user.findUnique({ where: { id: userId } });
  if (!user?.password) throw new Error('Password login not enabled for this account');

  const passwordMatch = await bcrypt.compare(input.currentPassword, user.password);
  if (!passwordMatch) throw new Error('Current password is incorrect');

  if (input.newPassword.length < 8) throw new Error('Password must be at least 8 characters');

  const hashedPassword = await bcrypt.hash(input.newPassword, 10);
  await prisma.user.update({
    where: { id: userId },
    data: { password: hashedPassword },
  });

  return { success: true };
}
```

```typescript
import { useState } from 'react';
import { useTransition } from 'react';
```

### Anti-Patterns to Avoid

- **Client-side filtering only:** Filtering all projects in memory defeats the purpose of server-side search; scales poorly with large datasets. Always query the database.
- **Search without debounce:** Sending a request on every keystroke creates unnecessary database load. Use `useDebouncedCallback` with 300ms delay.
- **Hardcoding breadcrumb labels in routes:** Labels should be fetched from the database to show actual team/project names, not slugs or IDs.
- **No soft-delete filtering in search:** When displaying archived projects, ensure `where: { deletedAt: null }` filters them out by default, and only show archived when explicitly filtered.
- **Password forms without current password verification:** Always require current password before allowing a new password to prevent unauthorized changes.
- **Storing plain passwords:** Always hash with bcryptjs before writing to the database; compare with `bcrypt.compare()`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|------------|-------------|-----|
| Case-insensitive string search | Custom regex or string manipulation | Prisma `contains` + `mode: 'insensitive'` | Database-level filtering is faster and handles Unicode correctly |
| Debouncing search input | setTimeout with manual cleanup | `use-debounce` library `useDebouncedCallback` | Handles cancellation, cleanup, and multiple invocations correctly |
| Breadcrumb state management | Redux or Zustand store | React Context (BreadcrumbContext) | Overkill for breadcrumbs; Context is sufficient and avoids extra dependencies |
| Password hashing | SHA-256 or MD5 | bcryptjs with cost factor 10 | bcrypt is specifically designed for passwords; provides salting and cost scaling |
| Sort/filter dropdown menus | Custom position math | Simple absolute positioning + onClick handlers | Fixed positioning relative to button works for dashboard use case |
| User profile editing | Multiple separate forms | Single form with `useTransition` + server actions | Cleaner code, automatic loading states, no API layer needed |

**Key insight:** Search, breadcrumbs, and settings are foundational features but implement straightforward patterns. The temptation to hand-roll them comes from overestimating the complexity. Use proven libraries and Next.js primitives instead.

## Common Pitfalls

### Pitfall 1: Search Query Injection via `contains`
**What goes wrong:** User types SQL-like input (e.g., `project'; DROP TABLE--`) into search. While Prisma parameterizes queries, `contains` with special regex characters like `%` and `_` can cause unexpected matches.

**Why it happens:** Developers forget that `contains` uses SQL LIKE under the hood, where `%` matches any character(s) and `_` matches any single character.

**How to avoid:** Escape special characters before passing to Prisma, or validate input length and character set. Keep queries simple.

**Warning signs:** Search returns unexpected results for special characters; queries time out on certain inputs.

### Pitfall 2: Infinite Loops in Breadcrumb Context
**What goes wrong:** Setting breadcrumb label in effect → triggers re-render → effect runs again → infinite updates.

**Why it happens:** useEffect dependency array missing or circular; context value changes trigger effect repeatedly.

**How to avoid:** Include `[segment, breadcrumbContext]` in effect dependencies. Only update context when segment or label actually changes. Memoize context value with `useMemo`.

**Warning signs:** Component re-renders excessively; memory usage grows during navigation.

### Pitfall 3: Archived Projects Visible in Search Results
**What goes wrong:** Deleted projects (soft-deleted with `deletedAt != null`) appear in search results by default.

**Why it happens:** Forgot to add `deletedAt: null` filter to the Prisma query; forgot that Phase 5.2 added soft-delete.

**How to avoid:** Always include `where: { deletedAt: null }` in searchProjects. Add a separate archived filter that explicitly includes `deletedAt: { not: null }`.

**Warning signs:** Users see deleted projects in grid; right-click context menu shows "Delete" but shouldn't.

### Pitfall 4: Password Change Without Session Refresh
**What goes wrong:** User changes password successfully but session remains active; can log out and back in with new password, but current session doesn't update.

**Why it happens:** Password hash updates in database but JWT session remains valid until expiry.

**How to avoid:** After password change, optionally trigger session refresh via `useSession().update()` from next-auth, or document that session remains valid until next login. This is acceptable for v1.

**Warning signs:** User reports being able to use old password temporarily; confusion about session state.

### Pitfall 5: Sort Not Persisting with Pagination
**What goes wrong:** User sorts by "Last Modified" and clicks next page, but sorting resets to default.

**Why it happens:** URL params for sort not preserved when adding `page` param; forgot to carry sort state across pagination links.

**How to avoid:** URLSearchParams constructor preserves all existing params. Just add/update the new param: `params.set('page', '2')` keeps existing `sort`, `filter`, `q`.

**Warning signs:** Users click to next page and see different sort order; sort dropdown shows one value but results are sorted differently.

### Server-Side Search with Prisma

```typescript
// Source: Prisma docs + Next.js pattern
export async function searchProjects({
  query = '',
  sort = 'name',
  filter = 'all',
  teamId,
}: {
  query: string;
  sort: 'name' | 'modified' | 'opened';
  filter: 'all' | 'recent' | 'starred' | 'archived';
  teamId?: string;
}) {
  const session = await getServerSession(authOptions);
  const userId = (session?.user as { id?: string })?.id;
  if (!userId) throw new Error('Unauthorized');

  const where: any = {
    team: {
      members: { some: { userId } },
    },
    deletedAt: filter === 'archived' ? { not: null } : null,
  };

  if (teamId) where.teamId = teamId;

  if (query.trim()) {
    where.name = {
      contains: query.trim(),
      mode: 'insensitive', // PostgreSQL: uses ILIKE
    };
  }

  const orderBy = {
    name: sort === 'name' ? 'asc' : undefined,
    updatedAt: sort === 'modified' ? 'desc' : undefined,
    lastOpenedAt: sort === 'opened' ? 'desc' : undefined,
    createdAt: sort === 'name' ? undefined : 'desc',
  };

  return prisma.project.findMany({
    where,
    orderBy: Object.fromEntries(
      Object.entries(orderBy).filter(([_, v]) => v !== undefined)
    ),
    select: {
      id: true,
      name: true,
      teamId: true,
      team: { select: { name: true } },
      thumbnailUrl: true,
      updatedAt: true,
      lastOpenedAt: true,
      deletedAt: true,
    },
  });
}
```

```typescript
'use client';
import { useDebouncedCallback } from 'use-debounce';
import { useRouter, useSearchParams, usePathname } from 'next/navigation';
import { Search } from 'lucide-react';

export function SearchInput() {
  const router = useRouter();

  const handleSearch = useDebouncedCallback((term: string) => {
    const params = new URLSearchParams(searchParams);
    if (term.trim()) {
      params.set('q', term.trim());
    } else {
      params.delete('q');
    }
    router.replace(`${pathname}?${params.toString()}`);
  }, 300);

  return (
    <div className="relative">
      <Search className="absolute left-3 top-1/2 -translate-y-1/2 w-4 h-4 text-zinc-500 pointer-events-none" />
      <input
        type="text"
        placeholder="Search projects…"
        defaultValue={searchParams.get('q') ?? ''}
        onChange={(e) => handleSearch(e.target.value)}
        className="w-full bg-zinc-800/60 border border-zinc-700 rounded-lg pl-9 pr-4 py-2 text-white placeholder-zinc-500 focus:outline-none focus:border-indigo-500"
      />
    </div>
  );
}
```

### Password Change with Validation

```typescript
// Source: NextAuth + bcryptjs pattern
'use server';
import { prisma } from '@/lib/prisma';
import { getServerSession } from 'next-auth/next';
import { authOptions } from '@/lib/auth';
import bcrypt from 'bcryptjs';

export async function changePassword(input: {
  currentPassword: string;
  newPassword: string;
  confirmPassword: string;
}) {
  const session = await getServerSession(authOptions);
  const userId = (session?.user as { id?: string })?.id;
  if (!userId) throw new Error('Unauthorized');

  // Validation
  if (input.newPassword !== input.confirmPassword) {
    throw new Error('Passwords do not match');
  }
  if (input.newPassword.length < 8) {
    throw new Error('Password must be at least 8 characters');
  }
  if (input.newPassword.length > 128) {
    throw new Error('Password is too long');
  }

  const user = await prisma.user.findUnique({ where: { id: userId } });
  if (!user?.password) {
    throw new Error('Credential-based login is not enabled for this account');
  }

  const passwordMatch = await bcrypt.compare(input.currentPassword, user.password);
  if (!passwordMatch) {
    throw new Error('Current password is incorrect');
  }

  const newHash = await bcrypt.hash(input.newPassword, 10);
  await prisma.user.update({
    where: { id: userId },
    data: { password: newHash },
  });

  return { success: true, message: 'Password changed successfully' };
}
```

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Client-side filtering from loaded array | Server-side Prisma query with `contains` | 2020s (with Next.js 13+) | Scales to unlimited projects; enables real-time filtering |
| Full-text search always requires Elasticsearch/Algolia | PostgreSQL native `tsvector` or Prisma `contains` + `mode: 'insensitive'` | 2019+ | Sufficient for most v1 apps; FTS libraries still useful for ranking/phrases |
| Breadcrumbs via segment ID lookup only | Breadcrumbs with context-injected labels from DB | 2023+ (with React Context) | User-friendly labels instead of IDs; flexible without prop drilling |
| Password stored as salt + hash separately | bcryptjs with integrated cost factor | 2010s+ (standard) | Simpler API; cost scaling prevents rainbow tables |

**Deprecated/outdated:**
- **Client-side search:** Filtering in memory; doesn't scale and blocks UI.
- **Full-text search only via external API:** Still valuable for ranking/faceting, but modern databases handle basic search.
- **Hardcoded breadcrumb labels:** Defeats the purpose of showing user-friendly names.

## Open Questions

1. **Full-Text Search: PostgreSQL `tsvector` vs. Prisma `contains`?**
   - What we know: `contains` + `mode: 'insensitive'` works for name matching; PostgreSQL's tsvector offers ranking and phrase search.
   - What's unclear: When should we upgrade to tsvector? v1 or v2?
   - Recommendation: Start with `contains` for v1. Monitor query performance. Upgrade to tsvector in Phase 6 (Marketplace) if search volume justifies it.

2. **Search: Breadcrumb labels for deeply nested routes?**
   - What we know: Context pattern works for Team → Project navigation.
   - What's unclear: What if we add sub-routes under projects (e.g., /dashboard/teams/[teamId]/projects/[projectId]/settings)?
   - Recommendation: Extend BreadcrumbContext to accept a map of `{ segment: label }`. Fetch project name server-side and pass to client via props/context.

3. **Settings: Avatar upload or URL only?**
   - What we know: Phase 5.3 plan specifies "avatar URL" in spec.
   - What's unclear: Should we allow direct image upload to R2, or just URL?
   - Recommendation: v1 = URL only (user manages upload externally). Phase 7 (Designer Profiles) can add direct upload via presigned R2 URLs.

4. **Search: Sort by "Last Opened" with null handling?**
   - What we know: `lastOpenedAt` can be null for never-opened projects.
   - What's unclear: Should nulls sort first or last?
   - Recommendation: Sort nulls last (never-opened projects below recently opened). Use Prisma's `nulls: 'last'` in orderBy.

5. **Settings: Settings page location and scope?**
   - What we know: Phase spec says "/dashboard/settings page exists."
   - What's unclear: Is this user account settings, or team settings too?
   - Recommendation: /dashboard/settings = user account (name, avatar, password). Team settings (invites, roles, members) remain at /dashboard/teams/[teamId]/members. Separate concerns.
