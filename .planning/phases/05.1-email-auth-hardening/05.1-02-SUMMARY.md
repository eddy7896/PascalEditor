# Phase 5.1 Plan 02: Email Verification Gating

## Summary

Added email verification requirement for new credentials-based signup. Users who register with email/password now receive a verification email and cannot access the dashboard until verified. Google OAuth users automatically set as verified (Google has verified their email). Existing credentials users grandfathered via migration.

**Core changes:**
- EmailVerificationToken Prisma model + migration
- VerificationEmail React template
- Signup endpoint creates token and sends email; returns success message (no dashboard redirect)
- /api/auth/verify-email?token=... endpoint consumes token, marks user verified, redirects to login
- CredentialsProvider.authorize() throws EMAIL_NOT_VERIFIED for unverified credentials users
- Google OAuth upsert sets emailVerified on account creation

## Must-Haves Verification

✓ **New credentials signup user receives verification email** — not a success redirect to dashboard
- Signup endpoint (POST /api/auth/signup) creates emailVerificationToken, sends VerificationEmail, returns { success: true, message: "Check your email..." }

✓ **Unverified user who tries to sign in gets an error** — not dashboard access
- CredentialsProvider.authorize() checks emailVerified, throws "EMAIL_NOT_VERIFIED" if null

✓ **User who clicks verification link gets emailVerified set and can sign in**
- /api/auth/verify-email?token=... validates token, updates user.emailVerified = now(), deletes token, redirects to /login?verified=true

✓ **Google OAuth users not blocked** — emailVerified set on upsert
- signIn callback Google branch: create block includes emailVerified: new Date()

✓ **Existing credentials users grandfathered** — not locked out
- Migration: UPDATE "User" SET "emailVerified" = "createdAt" WHERE "password" IS NOT NULL AND "emailVerified" IS NULL

## Architecture

### EmailVerificationToken Model

```prisma
model EmailVerificationToken {
  id        String   @id @default(cuid())
  token     String   @unique   // SHA-256 hash of raw token
  email     String
  expiresAt DateTime
  createdAt DateTime @default(now())

  @@index([email])
  @@index([token])
}
```

Stores hashed token; raw token never persisted. If DB is compromised, verification links remain safe.

### Signup Flow

1. User POST /api/auth/signup { email, password, name }
2. Endpoint creates User with password
3. Generates 32-byte random token → SHA-256 hash
4. Creates emailVerificationToken { token: hash, email, expiresAt: now + 24h }
5. Builds verify URL: `${NEXTAUTH_URL}/api/auth/verify-email?token=${raw}`
6. Sends VerificationEmail with link
7. Returns { success: true, message: "Check your email..." }
8. Frontend should show "Check your email" message, not redirect to dashboard

### Verification Link Consumption

1. User visits /api/auth/verify-email?token={raw}
2. Endpoint hashes raw → compares against DB
3. If found and not expired:
   - Transaction: UPDATE user.emailVerified = now(), DELETE token
   - Redirect to /login?verified=true
4. If not found or expired:
   - DELETE token if found
   - Redirect to /login?error=InvalidVerificationToken

### Login with Email/Password

1. User POST /api/auth/signin { email, password }
2. CredentialsProvider.authorize():
   - Query user by email (select: id, email, name, password, emailVerified)
   - Verify password via bcrypt
   - **NEW:** Check emailVerified; if null, throw "EMAIL_NOT_VERIFIED"
   - Return user object if verified
3. NextAuth handles error message in callback

### Google OAuth

- signIn callback, provider === "google":
  - Upsert user { where: email, create: { ..., emailVerified: new Date() }, ... }
  - Google has already verified the email; trust it
  - New accounts created as verified; can sign in immediately

## Key Implementation Details

### Token Security

- **Raw token:** 32 bytes random hex, sent only in email URL
- **Hash in DB:** SHA-256(raw token)
- **Rationale:** If DB is breached, URLs in email logs are unusable without the plaintext token. Matches password reset pattern (plan 05.1-01).

### Grandfather Migration

```sql
UPDATE "User"
SET "emailVerified" = "createdAt"
WHERE "password" IS NOT NULL
  AND "emailVerified" IS NULL;
```

Identifies existing credentials users by presence of password + null emailVerified. Sets verified timestamp to account creation date. No locked-out users.

### TTL

- Verification tokens: 24 hours (matches password reset)
- Expired tokens deleted on verification attempt
- No manual cleanup needed (cleanup on-demand)

### Email Template

VerificationEmail React component using @react-email/components:
- Props: { verifyUrl, name? }
- Preview: "Verify your Pascal email address"
- Body: greeting, CTA button "Verify email", "Expires in 24 hours", "Ignore if not you"
- Styling: black button, inline styles (React Email best practice)
