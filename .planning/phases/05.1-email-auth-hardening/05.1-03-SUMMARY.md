# Phase 5.1 Plan 03: Email Rate Limiting

## Summary

Implemented per-endpoint rate limiting on authentication endpoints using Redis with atomic Lua scripting. Three auth routes now protected against brute force and credential stuffing attacks: signup, forgot-password, and NextAuth credentials login. Each endpoint has isolated quota using prefixed Redis keys.

**Core changes:**
- Created `lib/rate-limit.ts` with atomic Lua fixed-window rate limiting helper
- Wired rate limiting into signup endpoint (5 requests/60s per IP)
- Wired rate limiting into forgot-password endpoint (5 requests/60s per IP)
- Wired rate limiting into NextAuth credentials login (10 requests/60s per IP)
- Fixed pre-existing JSX file extension issues (.ts → .tsx) to resolve TypeScript parsing errors

- All rate limiting in Node.js route handlers only
- ioredis not imported in middleware.ts

## Architecture

### Rate Limit Helper

`lib/rate-limit.ts` exports:
```ts
export async function rateLimit(
  key: string,
  limit: number,
  windowSec: number
): Promise<RateLimitResult>
```

Returns:
```ts
{
  allowed: boolean      // count <= limit
  remaining: number     // max(0, limit - count)
  count: number         // current counter value
}
```

### Lua Script

Fixed-window algorithm:
```lua
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local count = redis.call('INCR', key)
if count == 1 then
  redis.call('EXPIRE', key, window)
end
return count
```

- INCR atomically increments counter
- If first increment, set TTL to window (60 seconds)
- Subsequent increments within window accumulate
- After window expires, counter resets on next request

### Per-Endpoint Usage

**Signup:**
```ts
const ipHeader = req.headers.get('x-forwarded-for');
const ip = (ipHeader?.split(',')[0] ?? 'unknown').trim()
const { allowed } = await rateLimit(`rl:signup:${ip}`, 5, 60)
if (!allowed) {
  return NextResponse.json({ error: 'Too many requests...' }, { status: 429 })
}
```

**Forgot-Password:**
```ts
const ipHeader = req.headers.get('x-forwarded-for');
const ip = (ipHeader?.split(',')[0] ?? 'unknown').trim()
const { allowed } = await rateLimit(`rl:forgot-password:${ip}`, 5, 60)
if (!allowed) {
  return NextResponse.json({ error: 'Too many requests...' }, { status: 429 })
}
```

**NextAuth Credentials:**
```ts
const url = new URL(req.url);
const isCredentialsSignin =
  url.pathname.endsWith('/signin/credentials') ||
  url.searchParams.get('action') === 'credentials';

if (isCredentialsSignin) {
  const ipHeader = req.headers.get('x-forwarded-for');
  const ip = (ipHeader?.split(',')[0] ?? 'unknown').trim();
  const { allowed } = await rateLimit(`rl:login:${ip}`, 10, 60);
  if (!allowed) {
    return NextResponse.json({ error: 'Too many requests...' }, { status: 429 });
  }
}

return handler(req, ctx);
```

## Key Implementation Details

### IP Extraction

```ts
const ipHeader = req.headers.get('x-forwarded-for');
const ip = (ipHeader?.split(',')[0] ?? 'unknown').trim();
```

- Optional chaining: `ipHeader?.split(',')[0]` safely handles null header
- Fallback: `?? 'unknown'` if no header (preserves rate limit cohesion for any single no-header client)
- x-forwarded-for comma-separated list: take first (client IP) before proxies
- Trim whitespace from header value

### Endpoint Detection (NextAuth)

Credentials signin can be invoked via:
- POST /api/auth/signin/credentials (pathname ends with `/signin/credentials`)
- POST /api/auth/callback/credentials with action=credentials query param

Both patterns detected to ensure all credentials attempts are rate-limited.

### Rate Limits Chosen

- **Signup/Forgot-Password:** 5/60s — typical user flows allow 1-2 attempts; 5 accommodates delays + retries
- **Login:** 10/60s — higher threshold for legitimate user retry patterns (password typos, 2FA delays)
