  <action>
  Import `writeAuditLog` from `@/lib/audit` and `AuditEventType` from `@prisma/client` in both files.

  In `apps/editor/app/dashboard/actions.ts`, after the primary mutation succeeds (NOT inside any `prisma.$transaction`), add fire-and-forget audit writes:

  1. `changeTeamMemberRole` — after `prisma.teamMember.update`:
     ```ts
     writeAuditLog({
       teamId,
       actorId,
       targetId: targetUserId,
       event: "ROLE_CHANGED",
       meta: { oldRole: targetMembership.role, newRole: role },
     }).catch((err) => console.error("[audit] ROLE_CHANGED write failed:", err));
     ```

  2. `removeTeamMember` — after delete:
     ```ts
     writeAuditLog({
       teamId,
       actorId,
       targetId: targetUserId,
       event: "MEMBER_REMOVED",
       meta: { removedRole: targetMembership.role },
     }).catch((err) => console.error("[audit] MEMBER_REMOVED write failed:", err));
     ```

  3. `createProject` — after `prisma.project.create`. Only emit when project belongs to a team (skip personal projects):
     ```ts
     if (project.teamId) {
       writeAuditLog({
         teamId: project.teamId,
         actorId,
         targetId: project.id,
         event: "PROJECT_CREATED",
         meta: { projectName: project.name },
       }).catch((err) => console.error("[audit] PROJECT_CREATED write failed:", err));
     }
     ```

  4. `deleteProject` — after soft-delete update. Same teamId guard.

  In `apps/editor/app/api/teams/invite/accept/route.ts`, after the membership upsert transaction completes, add:
  ```ts
  writeAuditLog({
    teamId,
    actorId: userId,         // joining user is their own actor
    targetId: userId,
    event: "MEMBER_JOINED",
    meta: { role: invite.role },
  }).catch((err) => console.error("[audit] MEMBER_JOINED write failed:", err));
  ```

  CRITICAL: All writes must be OUTSIDE any `prisma.$transaction` and use `.catch()` so audit failures never roll back primary mutations. Match the existing fire-and-forget email pattern.
