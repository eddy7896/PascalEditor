# Phase 5.4 Plan 04: Email Templates + Notification Triggers Summary

**One-liner:** Two React Email templates (RoleChangedEmail, TeamAddedEmail) plus fire-and-forget email + notification triggers wired at all three callsites, completing Phase 5.4.

## What Was Built

### Task 1: Email Templates

- `RoleChangedEmail.tsx` — shows old→new role, optional actor name, View Team CTA button
- `TeamAddedEmail.tsx` — shows team name, assigned role, optional inviter name, Open Team CTA button
- Both follow `TeamInviteEmail` conventions: `@react-email/components`, inline styles, footer copy

### Task 2: Email + Notification Triggers at 3 Callsites

**Callsite 1: `changeTeamMemberRole` in `actions.ts`**

- After audit log write: fetches target user, team name, actor name in parallel
- Calls `sendRoleChangedEmail` helper (fire-and-forget)
- Calls `createNotification` with `ROLE_CHANGED` type (fire-and-forget)

**Callsite 2: `accept/route.ts` (invite accept)**

- After audit log write: fetches team + inviter in parallel
- Calls `sendTeamAddedEmail` helper (fire-and-forget)
- Calls `createNotification` with `ADDED_TO_TEAM` type (fire-and-forget)

**Callsite 3: `clone/route.ts` (marketplace clone)**

- Updated asset `findUnique` to select `authorId` and `title` (previously missing)
- After Promise.all: if asset has distinct authorId, calls `createNotification` with `SCENE_DUPLICATED`

### Helper Wrappers

- `lib/emails/role-changed.tsx` — builds JSX and calls `sendEmail`, imported by `actions.ts` which cannot contain JSX
- `lib/emails/team-added.tsx` — same pattern for invite accept route

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `clone/route.ts` asset query missing `authorId` and `title`**

- Found during: Task 2 pre-edit check
- Issue: `include: { project: ... }` provided no scalar fields from the asset itself; `asset.authorId` would have been undefined, so SCENE_DUPLICATED notification would never fire
- Fix: Replaced `include` with explicit `select` that includes `id`, `title`, `isPublished`, `authorId`, and `project`
- Files modified: `apps/editor/app/api/marketplace/clone/route.ts`
- Commit: 11853c6

**2. [Rule 1 - Bug] TypeScript strict null: `session.user.email` not narrowed at notification block**

- Found during: Task 2 TypeScript check
- Issue: TS18047/TS18048 — despite earlier guard returning early if session is null, TS did not narrow `session` type at the notification block
- Fix: Used already-narrowed `sessionEmail` variable (derived at top of handler) instead of `session.user.email`
- Files modified: `apps/editor/app/api/teams/invite/accept/route.ts`
- Commit: 11853c6
